# PT Limawira Wisesa — Marketing Site

A Hugo + Decap CMS + Tailwind CSS website, deployed to Netlify.

> **TL;DR**
>
> ```bash
> yarn install
> yarn start         # dev server on http://localhost:3000
> yarn build         # production build → ./dist
> yarn build:preview # draft build (for Netlify previews)
> ```
>
> The CMS lives at **`/admin/`** on the live site. Editors log in with
> Netlify Identity; everything that matters is editable there.

## 3. Editing content

### 3.1 Where to edit

For **non-technical editors**: open `/admin/` on the live site (or run
`yarn start` and go to `http://localhost:3000/admin/`).

For **engineers** (or quick edits via Git):
- Pages: `site/content/<section>/_index.md` (or `site/content/_index.md`)
- Solutions: `site/content/solutions/<slug>.md`
- Posts: `site/content/posts/<slug>/index.md`
- Global brand/contact/social/footer: `site/data/site.json`

### 3.2 The CMS schema

The CMS schema is **`site/static/admin/config.yml`**. Every page, field, and
option that an editor can change must be declared here. The schema is
deliberately verbose and uses the following conventions:

- **`pages` collection** — all single-file pages (home, about, contact, …)
- **`solutions` collection** — each solution is a separate markdown file
  under `/solutions/<slug>/`
- **`posts` collection** — blog/news under `/posts/<slug>/`
- **`site_settings` collection** — global brand & footer in
  `site/data/site.json`, plus a `hugo.toml` view for the site title

> **Rule of thumb:** if a non-developer is going to want to change it,
> add it to `config.yml`. Never make a non-developer edit a Hugo template.

### 3.3 Adding a new solution

1. In the CMS, go to **Solutions → New Solution**.
2. Fill in the slug, title, short description, hero, description, features
   (3 cards), specs, customers, and CTA.
3. The home page's "Our Solutions" grid reads from this collection, so
   the new card appears automatically.

To choose a different icon for the home-page card, edit
`site/content/_index.md` (`solutions.items[].icon` in the Home Page entry).

### 3.4 Adding a new page

1. Create a new file `site/content/<section>/_index.md` (and the
   matching folder).
2. Create a new template at
   `site/layouts/<section>/list.html` (or reuse `_default/list.html`).
3. Register the page in `site/static/admin/config.yml` under the
   `pages` collection.

> The CMS only lists pages that are explicitly registered in
> `config.yml`. If you create a new markdown file but don't add it to the
> schema, it will be live on the site but not editable from `/admin/`.

### 3.5 Icon catalogue

Icons are inline SVG strings in `site/layouts/partials/icon.html`. Add a new
`{{ else if eq $name "your-icon" }}` case to add a new icon. The home page
"Quick links" and solutions grid reference icons by name; the CMS
"icon" `select` widgets enumerate the available names.

## 4. Forms

The contact form on `/contact/` is a plain HTML form with
`data-netlify="true"` and a hidden `form-name` field. Netlify intercepts
the submission, stores it in the **Forms** tab of the Netlify dashboard,
and emails it to whatever address is configured there.

To add or remove form fields:

1. Update the `form.fields` list in
   `site/content/contact/_index.md` (or via the CMS).
2. The template `site/layouts/contact/list.html` iterates over this list
   and renders the right input for each `type` (`text`, `email`, `tel`,
   `textarea`, `select`).
3. Add a honeypot field (`bot-field`) — already in place.

## 5. Local development

### 5.1 Install

You need a working Hugo installation **on your machine**, then:

```bash
brew install hugo            # macOS
# or: choco install hugo    # Windows
# or: snap install hugo      # Linux
```

We use Hugo **0.124.1** in production. Check with `hugo version`.

```bash
yarn install
# or
npm install
```

This installs webpack, Tailwind v4, and the Decap CMS runtime
(which is loaded from CDN at runtime — no node dep needed for the CMS).

> **Why not `hugo-bin`?** Earlier versions of this project shipped with
> the [`hugo-bin`](https://www.npmjs.com/package/hugo-bin) npm wrapper
> so that `yarn install` would download a Hugo binary. That approach
> proved fragile on Netlify's build environment (the binary often
> failed to land in `node_modules/hugo-bin/vendor/` because the
> package's postinstall step was skipped in the build cache). The
> current setup uses Netlify's first-class Hugo support
> ([`HUGO_VERSION` env var](https://docs.netlify.com/configure-builds/manage-dependencies/#hugo))
> for production and a system Hugo for local development.

### 5.2 Run

```bash
yarn start
```

This runs `hugo` and `webpack-dev-server` in parallel. The dev server is
on `http://localhost:3000` and live-reloads on file changes.

### 5.3 Test the CMS locally

1. Run a [Netlify Dev](https://docs.netlify.com/cli/netlify-dev/) session
   (`npx netlify dev`) so the git-gateway can authenticate.
2. Visit `http://localhost:8888/admin/`.

The CMS config has `local_backend: true`, so Decap falls back to a
local proxy when no auth is available. This is enough for content
previews; production deploys use Netlify Identity.

### 5.4 Build

```bash
yarn build          # production → dist/
yarn build:preview  # drafts visible → dist/
```

The `dist/` folder is what Netlify publishes.

## 6. Deployment

The site deploys to Netlify automatically on every push to `main`. The
build is configured in `netlify.toml`:

```toml
[build]
  command = "yarn build"
  publish = "dist"
```

- **Production**: every push to `main` triggers a production build.
- **Preview**: every PR gets a draft build (with future-dated posts
  visible) at a unique `*.netlify.app` URL.

### 6.1 Netlify Identity (CMS auth)

1. In the Netlify dashboard, go to **Identity** and enable it.
2. Under **Identity → Registration**, set the mode to **Invite only**
   so only invited users can edit.
3. Invite yourself (and your editors) by email.
4. Users get an email with a one-time link to set their password.
5. They then log in at `/admin/` and edit content.

Every CMS change commits to the `main` branch via Git Gateway, which
triggers a new production build.

### 6.2 Netlify Forms

The contact form is automatically picked up by Netlify Forms. View
submissions in **Netlify → Forms** in the dashboard.

## 7. Styling guide

### 7.1 Brand colours

Defined in `src/css/main.css` under `@theme`:

| Token            | Hex       | Use                              |
|------------------|-----------|----------------------------------|
| `brand-700`      | `#475b29` | Primary brand green (default)    |
| `brand-800`      | `#384825` | Hover/dark surfaces              |
| `brand-50`       | `#f3f6ee` | Soft brand backgrounds           |
| `brand-100`      | `#e2ead4` | Hover on soft brand              |
| `ink`            | `#0f172a` | Body text                        |
| `ink-muted`      | `#475569` | Secondary text                   |
| `cream`          | `#f7f5ef` | Section backgrounds              |
| `line`           | `#e2e8f0` | Borders, dividers                |

Use the Tailwind utilities (`bg-brand`, `text-brand-700`, `border-line`,
etc.) — they map to the tokens above.

### 7.2 Typography

- **Display / headings**: Plus Jakarta Sans (700, 800)
- **Body**: Inter (400, 500, 600, 700)
- Loaded from Google Fonts in `partials/head.html`

### 7.3 Utility classes defined in `@layer components`

- `.container-x` — max-width container with responsive horizontal padding
- `.btn`, `.btn-primary`, `.btn-secondary`, `.btn-ghost`
- `.card` — white card with border + soft shadow
- `.input` — form input style
- `.badge` — pill-shaped tag
- `.dot-grid` — decorative dot background used on hero & CTA
- `.eyebrow` — small uppercase label with green underline

### 7.4 When to add a component vs. just use utilities

If the pattern is reused 3+ times, add a component class to
`src/css/main.css`. Otherwise just use Tailwind utilities directly in the
template.

## 8. Conventions

- **No comments in code** unless they explain *why* something
  non-obvious is done. Templates are self-documenting.
- **Don't inline styles** — always prefer Tailwind utilities.
- **Don't edit `dist/`** — it's generated. Only commit `site/`, `src/`,
  and `*.config.js` / `package.json`.
- **Image placeholders**: the home hero, solution heroes, and most
  customer logos currently use `/img/...` paths that don't exist yet.
  Drop the real images into `site/static/img/` (and the CMS will handle
  uploads into the same folder).
- **Slug convention**: lowercase, hyphen-separated, no leading slash.
  E.g. `data-center`, `ups-solution`, `ict-infrastructure`.
- **Order matters**: the home page's "Our Solutions" grid is ordered by
  the `order` field in each solution's front matter (lower = first).

## 9. Troubleshooting

| Problem                                      | Fix |
|----------------------------------------------|-----|
| CMS preview doesn't load                     | Make sure `local_backend: true` is in `config.yml` and you're using `npx netlify dev` (or have Git Gateway enabled). |
| Changes in `/admin/` don't show up           | Check the deploy log in Netlify — the CMS commits to `main`, which triggers a build. |
| `ERROR module not found: @tailwindcss/postcss` | Run `yarn install` again — the new Tailwind v4 packages weren't installed. |
| Hugo build error: "unable to find section solutions" | Ensure `site/content/solutions/_index.md` exists. |
| Tailwind classes not generated               | Tailwind v4 auto-detects content. Make sure the `tailwindcss` glob in your build covers `site/layouts/**/*.html` and `site/content/**/*.md` — the current `webpack.common.js` is configured for the entry CSS, which `@import`s Tailwind; Hugo's HTML output is scanned at build time. |
| 404 in browser but file is in `site/static/` | Hugo serves `site/static/` at the site root. Reference images as `/img/...`, not `/static/img/...`. |
